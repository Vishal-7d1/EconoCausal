# Dataset Sources

## 1. Criteo Uplift Modeling Dataset (public dataset)

| Item | Detail |
|---|---|
| Publisher | Criteo AI Lab |
| Official page | https://ailab.criteo.com/criteo-uplift-prediction-dataset/ |
| Paper | Diemert, Betlei, Renaudin, Amini. "A Large Scale Benchmark for Uplift Modeling", AdKDD 2018 workshop (KDD 2018) |
| Version used | v2.1 (13,979,592 rows). An earlier version has about 25.3 million rows |
| Columns | 16: `f0` to `f11`, `treatment`, `exposure`, `visit`, `conversion` |
| Download | Official file: `criteo-research-uplift-v2.1.csv.gz`. A 10% sample can be loaded with `scikit-uplift` (`fetch_criteo(percent10=True)`) |
| Licence / usage terms | **To be confirmed on the official page before any redistribution.** Raw data is not committed to this repository |

### What the data is
Each row is an anonymous user from an online advertising experiment. Users were **randomly** assigned to be shown an ad (treated) or not (control), and the data records whether they later visited the advertiser's website and whether they converted (bought).

| Column | Type | Role | Description |
|---|---|---|---|
| `f0` to `f11` | float | X (features) | Anonymised user features, measured before treatment |
| `treatment` | 0/1 | T | 1 = user was in the treated group (about 85% of rows), 0 = control |
| `visit` | 0/1 | Y | User visited the website (average rate about 4.7%) |
| `conversion` | 0/1 | Y | User converted (average rate about 0.29%) |
| `exposure` | 0/1 | Not a feature | Whether the user was actually exposed to the ad. Measured **after** treatment, so using it as a feature would leak |

### Why we use it
- The treatment was randomised, so the difference between treated and control is a trustworthy estimate of the ad's effect. It is a clean benchmark for causal methods.
- It is real data at large scale, so it shows the method working on messy, real-world information.

### Limitations
- The treatment is an **ad impression**, not a price discount, so it does not match our Rs 10 / Rs 20 discount setting directly.
- Features are anonymised and cannot be interpreted.
- Conversion is very rare (about 0.3%), so effects are small and noisy.
- Duplicate rows are expected, because users are anonymous and identical rows can be different people. Do not drop them automatically.
- The dataset is large. Work on the 10% sample first. Raw files go in `data/raw/`, which is ignored by Git.

### Inspection
Run `python inspect_criteo.py` from this folder. It prints shape, types, missing values, treatment ratio, outcome rates by group, and the average uplift on visit and conversion.

## 2. Synthetic Pricing Dataset (generated by us)

| Item | Detail |
|---|---|
| Generated with | `generate_synthetic.py` (Python, fixed random seed 42) |
| Size | 20,000 customers, 11 columns (14 after cleaning) |
| Treatment | Discount of Rs 0, 10 or 20, assigned **non-randomly** (confounded on purchase history and recency) |
| Outcome | `purchased` (0/1) and `spend` |
| Ground truth | `synthetic_ground_truth.csv` holds the true effects, for evaluation only |
| Details | See `docs/dataset_dictionary.md` and `docs/cleaning_report.md` |

### Why we use it
We set the true discount effect ourselves, so we can check whether the DML model recovers it. It also matches the app's real setting (Rs 10 and Rs 20 discounts). Its effects are simulated and are not real-world evidence.

## 3. Optional extra: Rossmann Store Sales (Kaggle)
Used briefly for exploration only. Real daily store sales with a binary promotion flag. Promotion days averaged about 39% higher sales. Kaggle competition rules apply, so the data is not redistributed here.
